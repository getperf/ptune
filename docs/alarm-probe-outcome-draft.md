# ptuneの時計通知にOS標準通知と色付きイベント表示を選んだ経緯

編集段階はドラフト、帰結は暫定。対象は2026-10-09の会話とprobe検証。主Card [[2026-10-09-ptune-os-notification-probe]] は作成承認待ちで、現時点では参照先が未作成。正式配置候補はvaultの `_decision_outcome/2026-10-09-ptune-os-notification-probe-outcome.md`。

## 背景と課題

ptuneはFlutterのポモドーロタイマー・タスク管理アプリである。作業開始と終了をvivoactive 5の振動で知り、親子タスクと進捗を短時間で読み取ることを目指した。既存実装はスマホ本体のHapticFeedbackであり、時計へ転送するOS通知を発行していなかった。

長い親タイトルと重複する子タイトルがあるため、子名だけでは対象を識別できず、全文を詰め込むと時計画面で見切れる。このため本体から独立したptune-alarm-probeで通知経路と文面を比較した。

## 選んだ方向と理由

ユーザーはOS標準通知で検討を進める方針を示し、②の開始🟢・終了🔴表示を「判りやすい」と評価した。専用Garminアプリを作らず、スマホのローカル通知を標準のスマート通知経路で時計へ転送する方式を選んだ。これは機種別の通知設定や接続状態への依存をなくす判断ではない。

| 案 | 内容 | 今回の評価 |
|---|---|---|
| OS標準通知 | スマホが通知を発行し、既存の時計通知連携で受信 | 現在の検討経路として選択。時計への文字表示を確認 |
| Garmin専用連携 | スマホSDKと時計アプリを開発して通信・振動を制御 | 今回は採らない。時計操作・専用振動制御が必要になれば再検討 |

通知のレイアウトを画像で固定するより、タイトルと本文を短く分ける構成を採った。最初の親名付きタイトルは写真で見切れ、子の「検証」が単独の行へ折り返された。その後、イベントのみをタイトル、短縮親名・子作業名・進捗を本文へ分け、②を既定としてprobeに実装した。

## 確認範囲

| 項目 | 根拠・結果 | 限界 |

| 時計への文字表示 | 会話に添付された実機写真 | 振動・遅延や受信直後の状態は写真だけでは判定できない |
| ②の可読性 | ユーザーが「②が判りやすい」と評価 | 定量的な読取時間、他端末への汎用性は未計測 |
| probe実装 | 即時通知、OS予約、取消、比較表示を実装し解析・テスト2件・Android APKビルド成功 | 予約・取消・再予約の実機記録は未取得。iOSはビルド未検証 |
| ポモ数の共通書式 | ptuneのPomodoroInfo.toDisplayString()を確認 | probeの整数入力・旧書式はまだ変更していない |

図は使わず、方式比較と確認範囲の表で説明する。実機画像は既存作業ノートを根拠とし、この草稿には複製しない。

## 未確認と引継ぎ

`🍅x2 ✅x1.5`を通知にも使う案は検討中である。既存ptuneは実績を小数1桁で表示し、nullなら実績を省く。実績は経過時間をポモ単位へ換算した値であり、完了済みセッションの整数カウントに限定されない。

元の表示判断に残る確認は、新しいポモ書式・小数・絵文字の描画、短縮名による対象識別である。振動とロック中予約・取消・再予約、スマホOS等の環境情報も未記録。これらを未検証のまま検証完了とは扱わない。

ptuneへの導入は後続の別判断とする。開始・時間満了・手動停止を区別し、設定の永続化、権限確認、予約の取消・更新、二重通知防止を扱う。特に事前予約した本文へ終了時の確定実績を保証して載せることはできないため、開始時点の値と明記するか実績を省略するかを決める。後続Cardの受け先は未作成で、現在は導入検討文書へ整理した。
