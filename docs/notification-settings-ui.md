# タイマー通知設定UI

2026-10-10: B案の設定UI・保存・OS権限操作と、タイマー通知を接続した。
画面の「利用可能」は権限条件が揃った状態を示し、時計への到達確認ではない。

検証: 変更ファイルの静的解析と全テスト43件が通過。
AndroidビルドツールをGradle 8.14.3 / AGP 8.11.1 / Kotlin 2.2.20へ更新し、
`flutter build apk --debug --no-pub` が成功した。iOSビルドと端末上の設定操作は未確認。

## 表示と状態

- 自動で作業開始を通知、作業終了を通知の2スイッチ。初期値はOFF。
- 自動モードOFF時は開始スイッチを操作不可にし、保存値を保持する。
- 通知の利用状態は1行。タップするとOS通知・必要なAndroid端末での終了予約権限をシート表示する。
- 開始のみ有効なら終了予約権限の不足を要設定にしない。
- 両方とも実効無効なら未使用。読込失敗・確認失敗を未許可と区別する。
- OS設定からの復帰時と設定画面を開いたときに権限を再取得する。
- 既存バイブ通知をスマホ本体の振動へ改名。設定画面全体をスクロール可能にする。
- 未対応プラットフォームでは対象外と表示し、スイッチを操作不可にする。

## 通知接続

- 通知対象は作業の時間満了と、自動遷移での作業開始。
- 手動開始・再開・停止・リセット、止め忘れ防止による停止は追加通知を出さない。
- 自動モード中の手動開始と自動遷移による開始を区別する。
- 終了通知OFF、一時停止、停止、リセット時は予約取消。再開・タスク切替・権限やモード変更時は予約更新。
- 時間満了通知とアプリ内完了処理の二重発行を防ぐ。
- タスク保存・リモート同期を通知の成立条件にしない。
- 止め忘れ防止OFF時の終了タイトルは短い休憩(5分)／長い休憩(15分)を予定から生成する。デモモードは実際の秒数を使う。
- ユーザーの選択により、止め忘れ防止ON中は「🔴 作業終了」のみ。
- 開始本文は確定済み実績を既存書式で表示。終了本文は計画のみとし、未確定実績を省略する。
- Androidはアプリ全体の許可に加えて通知チャンネルの有効状態も確認する。
- AndroidはセッションIDごとの発行記録、iOSは同IDの予約期限・処理記録で二重発行を抑止する。iOSで予約期限を過ぎた場合は既存予約に任せ、アプリから再発行しない。
- 残り秒数の端数を切り上げ、アプリ内の時間満了がOS予約より早まらないようにする。
- 通知予約に失敗してもタイマーは継続。アプリ内で時間満了処理が動けば即時終了通知を試みる。OS通知未許可なら表示されない。

## 実機確認と範囲

- Pixel 8aと時計で、ロック中の終了通知、振動、取消後に届かないこと、再開後の通知時刻、二重通知がないことを確認する。
- 手動開始・再開・リセットでは開始通知がなく、休憩から自動で作業に戻るときだけ開始通知があることを確認する。
- iOSはWindows環境のためビルド・実機未検証。
- OS予約は通知だけを発行する。アプリが停止中のタスク集計・次セッションの自動開始を保証しない。
- Android再起動・強制停止後の予約復元、タイマー状態の永続化は今回の対象外。
- OSの通知抑制や時計への到達は別途確認が必要。
